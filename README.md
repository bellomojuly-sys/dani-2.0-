# Dani 2.0

Dani 2.0 is my personal planning assistant, rebuilt from scratch. The first version (11 agents) became impossible for me to control, so this version grows one small, verifiable step at a time.

## Vision

**Final goal:** Dani is my own AI, trained on my needs and life goals. It organises my tasks, does the ones it can, writes and calls for me, keeps my shopping list, keeps me on track, and has a personality I can chat with.

**By 13 November 2026 (Sprint 3 demo):** a working app I can talk to, by text or voice (Whisper). Dani reads my plan (my Tasks in Notion) and all my Google calendars, follows my planning rules, and organises things for me ("move Thursday's call to 4 pm", "plan my free time on Wednesday", "new task: …"). It shows every change first and writes it only after my yes. The front-end is the PWA of the first Dani, reused (roadmap V5, 4 November 2026).

**By December 2026:** the same app, reliable on a real week: it respects all my rules, says what slips and how far when something moves, and an evaluation set proves it still works after every change.

**Why it is worth building:** an assistant that reads a company's own tools, follows its rules and asks before it writes is a service I can offer to small companies (MG Integration).

## First MVP (Sprint 2, 5–16 October 2026)

A terminal program where one LLM chooses between three Python tools and returns a validated answer to "what should I do first?".

- **Input:** three hardcoded tasks and the question "what should I do first?"
- **Output:** the task IDs in priority order, each with a one-line reason
- **Validation:** the answer is accepted only if every task ID appears exactly once and no ID is invented

## How to run

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env   # then fill in the keys
python main.py          # the terminal run: one question, three tools (M01–M04)
python dashboard.py     # the dashboard: real Notion tasks + real calendars -> dashboard.html
python dashboard.py --demo   # same page from the saved fixtures, no Notion and no download
python server.py        # the live dashboard on http://127.0.0.1:8000 (Home, Calendar, Meal prep, Settings, chat)
python server.py --demo # the same with the saved fixtures; ticking writes nowhere
python server.py --host 0.0.0.0   # reachable from the phone on the same Wi-Fi; needs DANI_PIN in .env
```

`server.py` keeps tasks and events in memory, re-reads them every 60 seconds
and serves `web/`. My private settings (context, cycle, hidden events) are in
`data/settings.json`, ignored by git; `data.example/` shows the shape.
`OPENAI_API_KEY` is optional and switches voice input to Whisper.
`GOOGLE_SERVICE_ACCOUNT_FILE` is optional too: with it the calendars shared with
the service account are read and written through the Calendar API
(`gcal_client.py`), ticked events are deleted, and the chat can propose a move
that is written only after Confirm (`propose.py`).

`dashboard.py` needs `NOTION_TOKEN`, `NOTION_TASKS_DB_ID` and `GCAL_ICS_URL`
in `.env` (see `.env.example`); `DEEPSEEK_API_KEY` is optional for it: without
it the page is built with an honest "no verified priority". The page is written
to `dashboard.html` (ignored by git, it holds private data): open it in a
browser, it is laid out for the phone.

How a dashboard run works, module by module:

1. `notion_client.py` — one POST to the Notion API, pages mapped to typed `Task`s (`models.py`);
2. `ical_client.py` — each calendar's secret `.ics` downloaded and expanded in the next 7 days into typed `Event`s;
3. `dashboard.py` — the same bounded tool loop as `main.py` (`read_tasks` → `prioritize_tasks` → `validate_priority_result`), but `read_tasks` returns the real tasks; the priority is shown only if validated;
4. `planner.py` — study blocks placed deterministically in the free time (no Sunday, 09–20, max 7 h/day, min 30 min);
5. `render.py` — the HTML, in the style of the app mockup.

For the tests, coverage and mutation testing, install the dev tools too:
`pip install -r requirements-dev.txt`.
